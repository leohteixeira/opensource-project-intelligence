# ADR-029: Issue Snowflake IDs Through Database-Leased Nodes

## Status

Accepted

## Date

2026-08-21

## Context

The frozen API uses Snowflake identifiers and must support more than one API or worker replica.
JavaScript cannot represent arbitrary 64-bit integers exactly, and static worker identifiers are
easy to duplicate during deployment.

## Decision

Use a documented custom epoch and a signed-positive 64-bit Snowflake layout containing timestamp,
database-leased node identifier, and per-millisecond sequence. Each process holds an exclusive,
renewable node lease and stops issuing identifiers if the lease is lost. Clock regression within a
small configured tolerance waits; a larger regression fails closed and makes the process unready.

HTTP path parameters and JSON fields serialize every Snowflake as a base-10 string. PostgreSQL
stores them as `bigint`; the web client treats them as opaque strings and never parses them as
numbers.

## Alternatives Considered

### Alternative 1: Static node IDs

- **Description**: Configure a distinct numeric ID for every process.
- **Pros**: No lease table.
- **Cons**: Deployment mistakes create collisions and are difficult to detect before writes.
- **Why rejected**: The VPS may later run multiple replicas and correctness must fail closed.

### Alternative 2: Central ID service

- **Description**: Add a service that returns each identifier.
- **Pros**: One clock and sequence owner.
- **Cons**: Adds latency and another mandatory service for every entity creation.
- **Why rejected**: PostgreSQL leases provide sufficient coordination.

## Consequences

### Positive

- IDs are sortable, compact, globally unique within the deployment, and safe in JavaScript.
- Node collisions are detected through one authoritative lease table.

### Negative

- Identifier generation depends on wall-clock discipline and a valid lease.
- Tests require a controllable clock and lease fake.

### Risks

- Clock rollback can stop writes; operations status reports offset and readiness failure without
  silently issuing duplicates.

## Implementation Notes

The exact bit allocation, epoch, lease TTL, renewal interval, and rollback tolerance are versioned
constants tested at every boundary and documented in the repository architecture specification.
