# ADR-022: Reserve Every Project Lifecycle Transition for Admins

## Status

Accepted

## Date

2026-08-21

## Context

Pause, archive, restore, and permanent deletion affect shared collection, portfolio visibility,
read-only state, retained data, and Jobs. The product-role decision previously left Analyst pause or
restore ambiguous.

## Decision

Only Admins may pause, archive, restore, or permanently delete a Project. Analysts retain Project,
Repository, source, synchronization, correction, reanalysis, alert-rule, and radar-annotation
capabilities but cannot perform lifecycle transitions.

## Alternatives Considered

### Alternative 1: Analysts pause and restore

- **Description**: Reserve archive and deletion for Admins.
- **Pros**: Analysts can respond directly to collection concerns.
- **Cons**: Changes shared freshness and portfolio state outside governance.
- **Why rejected**: All lifecycle state was selected as Admin governance.

### Alternative 2: Analysts perform every non-destructive transition

- **Description**: Reserve only deletion for Admins.
- **Pros**: Maximizes Analyst autonomy.
- **Cons**: Allows broad shared-state changes and archive removal without Admin review.
- **Why rejected**: It weakens the fixed role boundary.

## Consequences

### Positive

- The permission matrix is simple and backend-enforceable.
- Shared lifecycle changes have a clear accountable role.

### Negative

- Analysts must coordinate with an Admin for operational pauses and restores.

### Risks

- An unavailable Admin could delay urgent pausing; alerting and Admin redundancy mitigate this.

## Implementation Notes

Lifecycle controls are absent for Viewer and Analyst clients and rejected by backend authorization.
